# Hackathon resource audit

October 20, 2026. Source catalogue: [Devpost resources](https://amazonappdev2026.devpost.com/resources).

| Resource | Applied result / evidence |
|---|---|
| [Agent Skills specification](https://agentskills.io/specification) | Parsed real YAML; checked naming, allowed keys, metadata values, description length, references and all current tools in `test/skill.test.ts`. The format spec defines local folder packaging and relative references. It defines no HTTP well-known discovery path; PairUp keeps its documented `/skills/pairup/SKILL.md` endpoint and server-card/llms links. |
| [MCP Apps official skill](https://github.com/modelcontextprotocol/ext-apps/blob/main/plugins/mcp-apps/skills/add-app-to-server/SKILL.md) | Audited existing 1.7.5 integration using the skill's lifecycle, host-style, safe-area and display-mode guidance. Handlers precede `connect()`; SDK handles initialization and auto-resize; HTML is self-contained; text fallback remains. Added host variables/fonts, safe-area padding and scrolling for fullscreen/pip. Kept the existing compatible SDK major. |
| [2025-11-25 transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) | `test/transport.test.ts` covers Origin, protocol headers, Accept, single-message POST, unknown sessions, SSE and DELETE. Explicitly reject arrays because the installed SDK also accepts older batches. |
| [Amazon Devices Builder Tools](https://developer.amazon.com/docs/adbt/get-started) | Installed npm **1.0.17** into ignored `.data/builder-tools`; connected our MCP client over stdio and called tools. After `set_project_context({config:{}})`, searches for Ring webhook signatures/Event History and Alexa+ MCP/Agent Skills returned the official Ring API and Alexa+ toolkit documents. This search covers the questions despite the package's Fire TV emphasis. No global agent settings were overwritten. Logs: `codex-builder-search.log` (ignored). See friction entry ADBT-1. |
| [Ring starter](https://github.com/AmazonAppDev/ring-api-helloworld) | Compared device route, auth helper, event route and webhook route. Same API origin, Bearer auth and JSON:API device normalization. Adopted human-readable fallback names and request-id dedupe. PairUp retains signature verification and the API reference's Event History route; the starter's event route reads its own webhook store. Added device pagination, safe-origin links, null end handling, bounded retry and expiry errors. |
| [Ring API reference](https://developer.amazon.com/docs/ring/api-documentation.html) | Verified `X-Signature`, raw-body HMAC, request-id dedupe, 429 `Retry-After`, 5xx backoff and device/event paths. Added unique request-id storage and tests. Local arrival-evidence policy accepts the preceding 30 minutes and up to one minute of clock skew; the ten-minute arrival correlation is separate. These are PairUp policies, not a claimed Ring-mandated replay window. |
| [Ring UX guide](https://developer.amazon.com/docs/ring/ux-design-guide.html) | Applied names, plain-language state labels, action guidance, keyboard targets, reduced motion and retention transparency to the point panel. See DESIGN.md. This is a hackathon prototype; Ring Appstore certification is a separate release process. |
| [Bee CLI](https://github.com/bee-computer/bee-cli) / [Bee Skill](https://github.com/bee-computer/bee-skill) | Verified `stream --json --types` and all six subscribed event names in the current CLI README. Official Skill/MCP plus PairUp Skill recipe added. Replayed the fixture locally; real device provenance remains a recording prerequisite. |
| [MCP Inspector](https://github.com/modelcontextprotocol/inspector) | Headless tools/list succeeds against local Streamable HTTP. Inspector reports 0 schema portability errors, 168 portability warnings across 18 tools. This is an interoperability probe, alongside focused spec tests; it is not a claim of full official certification. |
| AWS Builder | Runtime evidence collector added; mock/offline runs deliberately produce incomplete evidence. Live services are exercised by Tony after deploy. |
| Open Source | Verified public MIT pairing-core and hackathon-period commits. Three upstream issue drafts and two small patch candidates are under `upstream/`. Publishing stays with Tony. |
| Community / dev.to | A technical post draft is under `posts/devto.md`. Forums, office hours and newsletters require no integration work for this submission. |
| Fire TV | Outside the submitted product scope. |
